4. Layout & spacing

The rule underneath every section below this one: a primitive carries no outer margin. A button, a field, a tile, a hero, a speech bubble — every one of them stops exactly where its own border stops. Nothing on this site decides how much air goes above or below it. That is the caller's job, and .stack is how the caller does it.

Which is what makes a component portable: moving one from one page to another never brings its spacing with it, and a page that wants things closer together changes one class instead of fighting a margin it did not write.

No stack — what "no outer margin" looks like

Two real fields, as direct children of a plain block. Nothing is broken here: there is simply no air, because neither field claims any. This is the default state of every primitive on this page.

.stack — 1rem

A flex column with a gap, and the default answer. Every form on this site is one, and so is most of what sits under a hero.

.stack--tight — 0.4rem

For things that belong to each other rather than a sequence of separate asks — the camera form, and the list of hints on a game page.

Two gaps, and this section is the first time either has been shown. Both shipped with the rule itself, in the commit that adopted this kit, and /kit went straight from borders to the score header — so the one rule every component below depends on lived in a CSS comment and nowhere a page author would meet it (#59).

Finding that out cost .field its margin-bottom, which shipped in the same commit as the rule it broke. A <label> is inline, so in ordinary flow the margin never applied at all — which is why the fields in the first box above are touching, and why they were touching in §10 before this section existed. Inside a .stack the label becomes a flex item, the margin applies, and it adds to the gap: every form on this site measured 2rem, and .stack--tight measured 1.4rem. The three boxes above only became honest demonstrations when it came out.

There was a third step, .stack--loose at 1.8rem. It shipped with the other two and no page ever used it, so it is gone rather than given a use invented to keep it (#58's rule, taking its second branch for the first time). Putting a step back is one line — and it arrives with a demo here, because new design is drawn on this page first.

The standing colours

The four lines are standing() in src/render.js — the same call the dashboard makes — and each marker names only its band, so the copy is read out of content/economy.js rather than typed here. 7. Hero — three flavours

Top half of every game page. Either words or a picture, never both.

All three boxes above are hero() from src/render.js, and they are two flavours rather than three, because the picture flavour has two states both worth showing: the empty frame is what a game renders while its photograph is unshot — boot has already shouted about the missing file — and the one under it is what every game looks like on the night. The kicker is optional and the game page passes none today — no game has a number to put in one — so this page is showing a slot that works rather than one that is used.

The sentence under the picture is blurb(), and it is the escape hatch for the rule in the line above: the frame holds words or a picture, so a game that needs both says the second part out here. Teddy is the only game using it.

The third flavour is named here and not drawn: the 16:9 video embed on the rickroll card. Drawing it would mean this page fetching YouTube every time it loads, and that card is the only markup on the site that leaves the network at all. The footer lists it by name rather than letting it pass as undocumented.

10. Form fields

Forms POST and redirect. No client-side validation theatre.

field() from src/render.js, the same call onboarding makes for all nine of its fields. The label wraps the control instead of pointing at it with for — there is no id to keep in sync, which is the one way this markup can break silently, and it breaks by labelling the wrong box.

The last one is a select, which Guess Who uses to name a person — it carries a member id and shows a name, so nobody loses a point because their partner typed their pet name at the door. It draws its own arrow: .input sets -webkit-appearance: none, and a select without an arrow is a text box that refuses to be typed in.

11. Modal

Fires on every hint reveal, saying a different thing the first time a team ever asks (free, a gift) than every time after (the price, a fine). Built by hintModal() in src/render.js and rendered already open by the server, because the hint has been revealed and charged by the time it appears — it announces, it never asks. On a real page it sits outside .app — because anim-page animates a transform and a transformed ancestor would pin a position: fixed box to the page instead of the viewport — and first, ahead of it, so the box you are looking at is also the first thing read and the first thing tabbed to. That is the whole of this site's focus management (#31, ADR-document-order-instead-of-focus-management): no trap, no move-in, no restore, no script. Here it is at the end of the page instead, because this is the one place that opens it by hand.

Shown here in its paid framing. The free one is the same box with different words, and there is only one #hint-modal on a page — demoing both would mean a second copy, which is the thing this page no longer keeps.

14. Photos — the camera and the shots

Two of the ten tiles are photo tiles, so this is the half of the site nobody could look at without a phone, a party and a real submission behind it. All of it is shoot(), shot() and shots() from src/render.js — the same calls a game page makes.

The camera

Not a .btn. The file input is hidden by clipping inside its own label — never display: none, which would take it off the keyboard — and the label is the target. The face is the only thing that varies: the scavenger wears its prompt on it, so tapping the thing you have to photograph is what opens the camera.

One shot

A square that taps through to the full picture. The thumbnail is the one the camera already embedded in the file's EXIF — about 7KB against a 1.2MB photo, which is what keeps a tile full of them cheap on house wifi.

The yellow one is the download tile, and it is the reason this section matters more than it looks: it fires when a phone sends a format the browser will not draw — HEIC, off an iPhone — and until now it could not be seen without owning one. It names the format and downloads rather than showing a broken <img> or opening a blank page.

The strip

What a plain photo: true game renders under its hero. Neither photo tile on today's roster takes this path — both pay per unit and compose their own stage — so this is what a photo game that declares no units gets for free.

Only the newest one carries the arrival animation; the rest of the strip stays put.

The picture is public/img/kit-shot.jpg, the only image this page commits: a strip needs something in it, and /uploads/ is player data that does not exist on a fresh checkout. It is 160×120 and ~7KB — the size and shape of a real EXIF thumbnail — and it is a drawing, because this repository is public and nothing in the house belongs in it.

Both photo tiles arrange these into a list rather than a strip — see §15.

15. Unit rows — the list a tile pays by

Four of the ten tiles pay per unit rather than per answer, and all four put the same list on the page: the photo scavenger's ten prompts, Portrait of a stranger's gallery, Guess Who's dealt cards and Herd Mentality's five predictions. One unitRow() renders every one of them.

These classes said .prompt until #51. They are .unit now, because a prompt is one label of one unit — and three of those four pages have no prompt on them at all, just a card, a question, or a photograph with something somebody said.

Plain — one control that brought its own frame

The camera's dashed target and a field() are already boxes, so a row around them would be a box around a box. .unit carries no rules of its own: it is a hook, not a look.

Boxed — several things held together

A row takes the border, the shadow and the paper exactly when it has a label or a thumbnail to hold something against. That is derived rather than declared, so there is no flag to get wrong.

The retake is deliberately quiet — allowed and free, but never the thing being asked for, so it must not compete with the rows still open.

What is not here is the <form>. Every one of these rows sits inside one on a real tile — one per row on the scavenger, one around the whole list on Guess Who and Herd — and render.js renders no form action anywhere, because which route a control posts to is the page's business and not the design system's. That is the seam #51 settled, and the scavenger's missing send button is where you can see it.

16. The signature card — Sign Here's 3×3

One tile, open for every team from the first minute of the night, and the only grid on the site. card() and square() in src/render.js — the same calls the tile makes.

These classes said .cell until #60. They are .square now, because that is the word the glossary uses and the word the tile says out loud: write it in the square, three in a row. And .card itself was being worn by two unrelated things — this grid and the admin gallery's submission boxes — which is a collision rather than a synonym, and the cascade was quietly merging them.

Empty — how every team meets it

Nine traits, no names. The signature line is a non-breaking space rather than nothing, so the card does not jolt upward as squares fill — on a tile reopened twenty times a night that is the difference between a card and a flicker.

The nine traits above are the kit's, not the game's — the real ones live in content/games/bingo.js and are meant to be overwritten (#21). These are deliberately wider and narrower than any of them, so the box is proved against worse than it will get.

Part-signed — the state it spends the night in

Green is a square somebody signed. Signed derives itself from whether there is a name in it, so there is no flag to get wrong; the longest handle in the pool is CROISSANT, and it wraps rather than widening the column.

A line — and this is the one nobody can see without eight signatures

Yellow, with the heavier shadow, on every square of the line — a card holding two lines shows both rather than picking one. It is passed in rather than derived, because whether a square sits on a line is a fact about the card's geometry that only the scorer computes.

Yellow means finished, not correct — a line pays the whole tile instead of its squares, never on top of them (#8, #21), and the colour change is what says so. There is no wrong answer on a card: there is a line, or there is not yet.

Unlike §14 and §15, nothing is missing from this section. The grid takes no <form> — the one dropdown and the one name box sit underneath it and belong to the page — so an empty card, a part-signed one and a lit line are the entire component. That is what turned #60 into an extraction rather than another question about where the seam goes.
